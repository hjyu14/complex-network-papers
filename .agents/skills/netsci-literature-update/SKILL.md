# 网络科学文献更新

## 入口与规则

这是依赖 NetSci Observatory 仓库的项目技能，不是独立爬虫。先确定实际仓库根目录，检查 Git 状态及 `AGENTS.md`；若有 `.agents/HANDOFF.md`，按项目要求读取和更新。所有命令从实际根目录运行，不写死机器路径，也不从另一个旧 checkout 取配置。

开始时读取仓库 `docs/repository-layout.md`、`docs/collection-workflow.md`、`docs/screening-protocol.md` 和 `config/sources.json`。取证前读取 `docs/evidence-data-features.md`；准备收尾时读取本技能 [收尾与发布](references/closeout.md) 及仓库 `docs/publication.md`。规则与白名单只从这些现行文件读取；恢复旧轮使用其冻结 `inputs/`，不能静默套用新规则。

明确起止日期（含首尾）、采集截止日、期刊范围及本次是否仅预览。默认选当前白名单全部期刊；日期未指定且无法唯一确定时询问，不擅自把“更新”解释成某一天。“今天”按用户时区，报告实际读取时刻，不承诺当天尚未结束时的全天覆盖。单日窗口令起止相同；历史月份显式传入窗口，不修改全局日期来完成补采。现有采集器要求同年窗口，跨年拆成连续子窗口；长窗口按来源预算拆分，不放宽请求上限。

普通更新采用项目已确认的条件发布授权；用户说“只采集”“只预览”“不要推送”时优先遵守。技能被自动选中不等于收到更新请求：解释、检查状态和演练不触发采集或发布。不得启动定时任务、改科学规则、扩刊、改网页布局或部署配置。工具审批仍须正常完成。

## 执行

1. **选择或恢复轮次。** 检查 `config/release.json` 和已有轮次。新的独立窗口使用 `reports/runs/<run-id>/`；同一未封存任务在原目录恢复。检查冻结窗口、as-of、期刊和日志链，不重复初始化。优先审读已经缓存而未保存判断的材料。封存后变化走明确新轮／复议，不解除封存。重叠窗口和已收录 DOI 要识别；接收稿正式发表时保留旧依据，不重复收录或静默覆盖冲突。
2. **整刊登记与覆盖核对。** 使用 `scripts/collect_candidates.py`，新轮显式给 `--out`、`--as-of`、`--window-start`、`--window-end`；恢复用相同 `--as-of` 与 `--resume`，不再传窗口覆盖。按采集规程逐刊核对全部 ISSN、官方全类型目录、分页、边界、独有 DOI 和身份／日期冲突。连续更新须按采集规程核对跨轮重叠窗口、出窗条目的历史有效判断及接收稿状态变化；不能仅凭出窗或曾登记略过未审读条目。不以网络关键词裁剪候选，不以 Crossref 请求成功证明出版社完整覆盖。浏览器目录有必要时采用现有导入器或文档要求的日志事件，导入后恢复采集器核验。
3. **逐批取证和审读。** 新轮在候选稳定后初始化 `scripts/screen_candidates.py`；遵循现有 `collect-batch`、`review-pack`、`decide-pack`、`batch` 接口。先核验缓存，再按规程使用 Crossref、出版社、OpenAlex，必要时用当前可用浏览器工具补证。工具调用前读适用技能／工具说明。HTTP 失败不等于文章无摘要；浏览器不可用则记录具体故障和需要人工完成的最小动作。不得绕过验证码、访问控制或通过复制 cookie 恢复访问。429 按规程停止后续请求，不换渠道规避限流。
4. **实际作出判断。** 主代理逐篇阅读身份匹配的允许材料，记录网络对象、科学问题、主要贡献与纳入／排除理由，通过现有接口保存正式判断及输入哈希。脚本只取证、计数、校验，不能用关键词或材料可用标志代替审读。每批闭合后再开始下一批，尚未审读与已读未决分开。缺精确 Article/Letter 标签时应用当前规程，不能增加额外阻断。证据不足不得编造结论，单篇用户例外不得推广为普遍许可。
5. **补证并分类交付。** 对未决项继续安全、有预算的可用渠道；必要时用 `scripts/supplement_evidence.py` 恢复。保存实际用户裁决，不能把技能说明当作某篇文章的裁决。按收尾参考区分科学边界待裁决与资料缺口；已取得充分排除证据的文章不因非必要字段缺失继续向用户索要资料。整刊级缺口即使没有具体 DOI，也须独立列出。
6. **跨轮审计及有条件发布。** 连续更新按采集规程执行 `audit_carryover.py`，确保首次发现、出窗历史判断、题名／材料与接收稿状态变化已闭合；将审计显式绑定到发布清单，不以最新判断自动覆盖重复 DOI。两类人工队列均为空、无未审读／活跃项、无未解决覆盖或跨轮审计阻塞，且身份、日期、类型、作者、阅读说明、主题、重复 DOI 与发布校验通过，才按收尾参考继续发布。任一条件不满足则保留上次有效网站，交付具体待办；不能先发布已纳入部分并称本轮完成。

## 文件与结果

- 正式记录仅进入本轮 `reports/runs/` 或封存后的 `reports/reviews/`。遵守仓库规范，不每批创建一套 final、retry、summary 或逐篇报告；必要独立补证必须说明用途并绑定来源。
- 完整摘要只进入 Git 忽略的 `.private/abstract-cache/v9/`，保留来源、版本与哈希。`review-pack` 的摘要只在审读会话查看，不转存普通报告、终端日志或提交。临时书目转录、无摘要的判断草稿和可重建清单放 `.private/work/<run-id>/`；不保存正文、HTML、PDF、凭据。
- `manage_runs.py export --run ...` 只生成私有派生视图，不是完整人工待办报告，也不是最终裁决来源。收尾须另读正式状态、逐篇失败／判断及覆盖，不能只看导出中的已判断记录。
- 临时材料随轮次收尾，按仓库目录文档及收尾参考核对后清理；不在 `work/` 根目录累积批次文件，不把所有过程文件永久搬进 `history/`。清理权限与发布权限分开，不能仅凭文件名或任务已发布就删除。
- 用户最终收到：分类结果入口与计数；待人工 review 清单；待人工补资料清单；覆盖／技术阻塞及发布状态。两类清单为空也明确写“无”。详情和发布验收按收尾参考执行。
