# NetSci Observatory v9 逐篇审读规程（讨论稿）

本规程只定义下一版采集与审读的共同标准；在 v9 实现和试运行获准前，不改变当前网站生产数据。

## 1. 时间范围

- 网站目标窗口仍为最近 90 个日历日。
- 初始建池从 2026-09-01 开始；首次完整初始批次为 2026-09-01 至 2026-09-30。
- 不追溯 2026-09-01 以前的文章。
- 每日加入新发表文章并保留已审核记录；达到 90 天后，每加入一天便移除最早一天。
- 发表日期优先级为 online first、print、published/issued；日期不完整、未来日期或来源冲突时进入 review。
- 出版社明确标为 Accepted Paper 且尚无确认发表日期时，允许用完整接收日期确定窗口、排序和显示，日期注明“接收”，不将其改称发表日期。这是已接收文章的明确例外；其他日期规则不变。
- 2026-10-02 用户确认的 APS 日期裁定：同一 DOI 的 Crossref `published-online` 若与出版社明确标注的 Accepted 日期相同，而出版社已给出完整 Published 日期，则以出版社 Published 日期裁定，保存 Crossref 原日期、接收日期、发表日期和来源。若刷新后的 Crossref 已与出版社 Published 一致，记录为来源冲突已解决。不得将这一规则泛化为采用卷期日期，也不得由日期相同直接声称 Crossref 填错；不满足上述条件的来源冲突仍进入 review。

## 2. 候选范围

候选集合是白名单期刊在时间范围内的期刊文章，包括出版社明确确认已接收的 Accepted Paper。期刊身份、ISSN、DOI、文章类型和日期必须通过硬性检查。预印本、编辑部文章、勘误和其他非目标文章不进入收录结果。

- 2026-10-02 用户确认：核实为 Reply 的文章不纳入。类型核实须有同一 DOI 的出版社类型证据；出版社正式标题明确表述对具名 Comment 的 Reply，并与该期刊官方 Reply 格式定义相符，也可作为核实依据。不能把 Accepted Paper 状态当作文章类型，不能将此排除规则套用于 PRL 的研究 Letter。无摘要且其他证据不足的文章仍保留 review。

### 已接收与早期版本的显示（2026-10-01 用户确认）

- 已接收文章通过相同的 v9 主题筛选后进入正常文章列表，不设独立区域。
- APS 页面明确标为 Accepted Paper 时，文章卡片显示“已接收 / Accepted Paper”标记；不能仅凭 APS 期刊名称或缺少全文推断状态。
- 其他出版社已经在线发表的 Article in Press、Online First、FirstView 等按首次在线发表日期处理，无需等待最终 Version of Record、最终 PDF 或编入期号。复用已保存的明确版本标签；不要求为补标签逐篇访问页面，不因缺少版本字段进入 review。
- 保留接收日期、发表日期及各自来源。只有接收日期时注明“接收”；有确认的首次在线发表日期时按发表日期处理。
- 后续核实状态变化时更新同一 DOI 条目和标记，不新增重复文章。
- 本约定用于后续 v9 实现，当前材料收集报告中的“正式发表确认数”仍按其原定义保留。
- 2026-10-01 官方机制查证：Springer Nature 的 Article in Press 已属于早期发表，Published Date 是首次上线日期，Version of Record Date 是最终版本日期；制作中也可能校对正文，并非只有 PDF 排版未完成。详见 `reports/v9-2026-09/early-publication-mechanisms.md`。
- 非 APS 记录不设普遍版本复核任务；日期缺失或冲突，以及明确只有接收信息而无发表日期的记录，仍按既有补证规则处理。没有逐篇访问过的记录不能标成“出版社逐篇确认”。

## 3. 元数据来源

Crossref 用于批量发现和初始元数据。只有摘要、标题、日期、文章类型或期刊身份缺失或冲突时，才通过 DOI 解析到的出版商页面补充核对。页面不可访问或仍有冲突时进入 review；不得猜测，也不得绕过登录、付费墙或验证码。

### 本地私有摘要缓存（2026-10-02 用户授权）

- 允许将完整摘要保存于 `.private/abstract-cache/v9/`，仅用于本地筛选、复核和恢复工作；该目录必须由 Git 忽略。
- 完整摘要和缓存不得进入 Git 提交、普通报告、`site/` 或部署产物。网页仅展示元数据、简短收录说明及来源链接。提交前运行 `python scripts/check_private_abstracts.py`，检查 Git 索引中的私有路径和站点 JSON 摘要字段；不得使用强制添加规避保护。
- 缓存逐条保存 DOI、标题、来源 URL、获取时间、摘要字段/栏目依据和摘要 SHA-256；核对同一 DOI 后才写入。不同来源或内容版本保留，不覆盖旧证据。摘要内容变化时，旧审读结论不能自动套用。
- 优先读取并校验已有缓存。新获取的摘要先可靠保存，再逐批完成审读；审读记录引用摘要及输入哈希。分别报告“完整摘要已缓存”“已审读”和“待复核”，不得用可用性、字数或关键词代替完成状态。
- 2026-10-02 用户进一步明确：读取与筛选必须在同一工作批次内闭环。每篇读取成功后立即缓存并审读、记录结论；若采用小批读取，须先完成本批每篇的分类或明确的 review 原因，再启动下一批。不能先采完整池再开始分类，也不能把“尚未审读”伪装为“已审读但证据不足”。中断后优先处理已缓存未审读记录。
- 普通网页 description、搜索片段、正文摘录或生成式摘要不能冒充完整摘要；仅保留可用性标记的历史记录不算已有完整摘要缓存，须从已确认来源重新获取。
- 此例外不允许保存全文、原始 HTML、PDF、cookie 或密钥，不改变 v9 科学范围、日期、类型和无证据留 review 的规则。旧报告保留其历史含义；当前生产网站仍按原发布版本运行。

## 4. AI 审读边界

AI 只能使用标题、摘要、期刊、日期、文章类型及其来源证据。AI 不得使用开放式搜索、作者声誉、期刊名气或领域常识补充缺失事实。没有直接证据时必须输出 review。

## 5. 类别

- `core`：网络结构、网络上的动力学或复杂网络理论/方法是主要问题和主要贡献。
- `transferable_application`：研究具体系统，但网络科学方法或理论贡献明确且可迁移，不是常规领域网络分析。
- `excluded`：网络只是数据表示，或网络科学不是主要贡献，包括只应用成熟中心性、社区发现或网络推断工具的常规领域研究。
- `review`：摘要缺失、元数据冲突、证据不足或判断不稳定。

## 6. 可复现性

每次审读记录规程版本、配置哈希、模型版本、输入哈希、输出、证据短语和审读时间。规则或模型改变时，必须通过固定回归样本后才能用于生产。

## 7. 收录说明句

每篇收录文章生成一条面向读者的简短说明句，字段名为 `screening_summary`。说明句必须只有一句，并且具体指出研究对象、使用的网络科学操作或方法，以及因此符合收录范围的原因。优先使用标题和摘要中的具体名词，避免“研究网络科学”“具有重要意义”等宽泛表述；不得加入证据中没有的效果、创新性或因果结论。建议英文长度为 12–30 个词。说明句不足以支持判断时，文章进入 `review`。

例如，土壤重金属文章应写成类似：`Uses complex-network analysis to model soil heavy-metal pollution and construct an early-warning risk framework.` 而不是只写“applies network science to an important application”。

## 8. v8 边界案例校准

此前 6 篇待核查文章的确认结果为：前 5 篇排除，第 6 篇归入 `transferable_application`。这些结果作为 v9 的固定回归样本。作者单位、关键词或标题中的 `network` 只能辅助发现风险，不能单独构成纳入依据。
