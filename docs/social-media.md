# X 与小红书日常内容规则

## 范围与依据

本文件是两平台文案、配图和交付规则的单一来源，适用于日常文献更新收尾及用户单独请求准备社交材料。科学筛选和全文荐读继续遵守 `docs/publication.md`，本文件不改变其条件。社交材料由 agent 准备，用户手动发布；生成完成不等于已发布。本规则不创建或迁移定时任务。

- 以本期已经核验并上线的网站快照、更新记录及当期荐读为依据，绑定具体日期、来源轮次和 DOI，不根据目录名或上一次聊天的篇数猜测。
- 日期使用 `Asia/Shanghai`，表示本期更新日期；保留论文真实发表／接收日期，不将“今日收录”写成“今日发表”。新增收录与接收稿转正式发表分别统计，同一 DOI 不重复算新增。
- 每次周检的 PR／RMP 新增综述单列数量；非检查日说明未检查，不将其称为零新增。已确认的新增，X 逐篇跟帖、小红书正文和清单图均纳入相应题名、作者、真实首次在线日期、Review 状态及完整 DOI 链接，并提供 `https://netsciobs.com/reviews.html`。网站新增总数按普通馆藏与综述新增 DOI 并集计算；正文分清两类，不把综述数混入首页普通馆藏计数，也不重复计算共享 DOI。只有新增综述时也按本期新增准备材料；历史选集回填不写成当天新发表。
- 两平台沿用网站当期荐读，仅推荐已正式发表的文章，接收稿只能作为明确标注 Accepted 的普通新增文献介绍。突出阅读价值、方法启发与必要适用范围，区分论文结果和编辑判断。正文与图片不强调“未复现实验”，实际阅读／验证范围仍按原规则如实保存在正式依据中。
- 不在正文或图片中反复解释收录规则，不使用夸大结果或无依据的宣传表述。完整摘要、论文正文、私有路径及凭据不进入社交材料。
- 同日再次更新沿用已发布的当期荐读，合并新增材料；已知用户发布过的内容不重复包装成新一期，不自动声称已经检查过社交平台。

## X：英文串帖

默认采用“首帖汇总与荐读，后续一篇文献一条跟帖”，作为回复依次相连：

1. **首帖**：日期、网站新增数量及已发表／接收稿数量，另列接收转正式发表数量；结合当期 suggestion，交代作者、可辨认的研究主题与阅读价值，保留必要适用范围、荐读 DOI 及 `https://netsciobs.com/#suggestion`。首帖信息较完整，但仍遵守普通帖子长度预算。
2. **逐篇跟帖**：本期新增每篇一条，写可辨认的主题、作者、简短研究内容、期刊、真实发表／接收日期和该篇 DOI。先已发表、后接收稿；“本期收录”不能写成“今天发表”，接收稿明确标为 Accepted。荐读若已经在首帖介绍，不重复另起同篇跟帖。其他转发表文献逐篇作为状态更新跟帖，不混入新增数。

- DOI 使用完整 `https://doi.org/…` 链接，每条独立成行。
- 默认使用 `#NetworkScience` 加一个相关主题标签，每条最多两个；标签计入长度。
- 按普通帖子 280 的加权字符预算检查，URL 按 23 计，不能用原始字符串长度代替加权计数。优先使用官方 `twitter-text`；无法可靠验证时如实标为待发布框复核，不声称已通过平台计数。
- 各帖单独校验长度；优先压缩冗余和标签，保持一篇一帖，不把多篇 DOI 堆成清单。完整串帖保留全部新增 DOI；首帖网站荐读入口同时提供网站入口，篇幅允许时可补更新入口。
- 若有接收稿转发表，明确另列状态更新及对应 DOI，不混入新增数量。

计数依据：[X 官方计数说明](https://docs.x.com/fundamentals/counting-characters)。平台规则变化时核对当前官方说明。

## 小红书：方案 B

### 标题与正文

- 默认每天一篇中文图文。有新增时标题统一为 `MM.DD｜网络科学文献日更N篇`，例如 `10.22｜网络科学文献日更11篇`，保留“文献”二字；馆藏荐读使用对应名称。标题内部预算不超过 20 个字符，并复核发布框提示。
- 正文顺序：本期数量与发表状态 → 荐读的阅读价值和方法启发 → 分组文献清单 → 网站地址与话题。
- 保留荐读论文完整原文题名；其余文献使用明确标注为“主题概述”的中文短说明，加全部 DOI。主题概述不冒充正式译名。完整原文题名放在配图中，作者和其他书目信息可在网站查阅。
- 已发表与接收稿分组，后者明确待正式发表。状态更新单独说明。
- 每篇主题／题名与 `DOI：…` 分行，文献之间空一行；DOI 字符串不得插入空格或断开。网站入口使用 `netsciobs.com`。
- 正文以 1000 字符为硬上限，尽量控制在 900–950 以内；空格、换行、标点、emoji 和话题均纳入检查。记录统一为 LF 换行后的字符数及 UTF-16 长度，采用较大值控制，并为发布框差异留余量。平台发布框如仍提示超限，继续压缩后重新交付。
- 正文末尾固定使用 `#网络科学 #复杂网络 #高阶网络 #文献阅读 #科研日常`，按此顺序以空格分隔，使用纯文本话题而非 Markdown 链接，全部计入正文字符数；先压缩冗余说明，不能为了标签删 DOI。
- 主题概述与全部 DOI 仍超长时，拆为编号明确的多篇笔记；各篇分别提供标题、正文和对应配图，逐篇满足限制，不静默遗漏文献。

### 配图内容与每日变化

默认三个内容部分，可按篇数增加清单页：

| 部分 | 必须包含 |
|---|---|
| 更新封面 | 日期、总篇数、发表状态数量、荐读主题；馆藏模式使用真实对应标题 |
| 今日荐读 | 完整题名、作者、期刊与真实日期、阅读价值、方法启发、必要局限、DOI |
| 文献清单 | 全部新增文献的完整原文题名、发表状态、DOI；空间允许再加作者／期刊 |

- 保留 NetSci Observatory 品牌、网站入口、藏青主色及手机阅读所需的清晰层级；蓝紫点缀、纸张底纹和手绘风格可作为系列基调。
- **每日配图须有可见变化，不能直接复用昨日整套图只改日期和文字。** 制作前查看最近一期可用成品及设计记录；有多日材料时参考近期样式，避免连续重复。
- **封面保持网站的藏青主题格调，构图尽量每日不同。** 与昨日封面并排核对，至少改变主构图或主体视觉及其位置；仅改变折线走向、节点形状、日期或文字不算有效变化。品牌一致性主要由配色、字体层级和网站标识维持，不固定沿用同一封面模板。
- 根据当期主题调整主要插画、布局、标题处理、卡片形式或装饰元素中的至少一项主要视觉元素，通常搭配调整另一项细节。例如更换网络／书桌／笔记插画、调整标题区与插画位置、改变卡片和清单排法。保留系列辨识度，无需每日彻底重设计。
- 把每天采用的视觉方向及相对上一期的变化写入图片提示词记录；只有生成后实际检查过，才能声称已核对差异。
- 优先采用适合手机浏览的竖版构图。长题名通过合理换行和增加清单页处理，不靠持续缩小字号硬塞。学术示意插画不冒充论文真实结果图。
- 使用适用的图片生成／编辑技能；最终图片逐张查看，核对题名、作者、日期、DOI、数量、状态与可读性，修复文字错误后交付。提示词正确不能代替成品检查。

## 无新增、阻塞与交付状态

- **无新增但有当期完成并上线的馆藏荐读**：两平台照常准备“馆藏荐读”，说明本期无新增，不虚构清单或新增数字。X 可合并为一条荐读帖，小红书按内容安排封面／荐读页，不强造第三页。
- 无新增且无新荐读：不为更新而强造帖子，不把上期荐读改日期重发。
- 仅有接收稿转发表：准备明确标识的状态更新，必要时结合当期有效荐读。
- 网站更新存在未解决阻塞或尚未确认上线：报告问题，暂不交付为已完成的本期宣传材料。社交配图失败不回滚已验证的网站；可先交付标明缺项的文案，补图前不得称完整材料已交付。

## 文件保存与会话输出：两者都必须完成

每日材料固定保存到项目根目录下 `.private/work/social-post-YYYY-MM-DD/`，不进入 `site/` 或公开 Git 报告：

| 路径 | 内容 |
|---|---|
| `x-thread.md` | 按发布顺序排列的英文帖子，每条一个纯文本代码块，标注各条加权长度和校验状态 |
| `xiaohongshu-title.txt` | 可直接复制的标题 |
| `xiaohongshu-body.txt` | 可直接复制、使用实际换行的正文 |
| `images/` | 按上传顺序编号的最终配图 |
| `image-prompts.json` | 当期最终提示词、视觉方向及相对上期的变化 |
| `README.md` | 来源快照／轮次、当期 DOI 与荐读、字数及图片检查结果、缺项；注明材料待用户手动发布 |

正文拆篇时，对标题与正文使用匹配的 `-01`、`-02` 编号，图片对应分组。存在同名材料时先查看；同一期修改在用户授权范围内更新，已确认发布或用途不明的旧文件不得无依据覆盖。

**任务结束时必须同时在最终回复中直接输出以下内容，不能只给文件路径或让用户自行打开文件：**

1. 网站更新简要结果及必要人工待办。
2. X 各条最终文案：按顺序每条一个 `text` 代码块，序号和字数放在代码块外。
3. 小红书标题、正文：分别放在独立 `text` 代码块中，代码块内不加说明、Markdown 加粗或字数标记。
4. 配图按上传顺序给出可点击的本地文件链接，并给出整套材料目录入口。
5. 字数检查及材料是否齐备；明确社交平台仍待用户手动发布，不将文件写入成功当作发布成功。

会话内文案与保存文件必须一致，使用真实换行而非字面 `\n`。发布状态未知时保留未知；文案与图片是交付物，不得在本轮临时清理时提前删除。
