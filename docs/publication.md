# 审核快照发布

## 输入与轮次

`config/release.json` 明确列出完成的 `reports/runs/<run-id>/`，不自动扫描目录。支持同一窗口的不同期刊，以及相邻、互不重叠窗口的合并；每本展示期刊的窗口须连续覆盖发布范围。同一期刊同一窗口须有完全一致的覆盖及 DOI 集合，否则失败。各轮独立保留窗口、规则和输入哈希。

每轮发布读取自己的冻结规则、原始候选、覆盖、采集日志和最新正式判断。必须无活跃任务、未审读或未决项；纳入者通过全部必要硬检查。完整性标志保留来源核对实际限制，不改写历史状态。

后续补证可显式存于该轮 `publication-evidence.json`，须有日志绑定及逐文件哈希。公开汇总保留引用与补证结论，但不覆盖冻结的原始覆盖标志。单篇 `editorial_basis` 须绑定正确 DOI、题名、候选和用户裁决；延伸阅读保留非核心语义及单篇范围例外，不冒充可迁移网络科学主要贡献。

重复 DOI 只有候选、判断与公开记录一致才去重；冲突直接失败，须明确核查后追加修正，不能“最新记录优先”。作者、说明、材料与判断绑定继续逐篇验证。每轮仍是独立输入，多轮发布另保存轮次及各输入哈希。

### 每日重叠补采

完整重叠补采作为独立原始轮保留，并追加到 release；不删掉旧轮、修改旧窗口或重写旧判断。新轮 `publication.json` 可显式声明 `carryover_audit`，其 `file` 固定为 `evidence/cross-run-audit.json`，`sha256` 钉住文件字节；审核日志须有匹配 `carryover_audit_completed` 事件。发布器重新核验审计、此前全部选定清单、逐 DOI 新旧记录／判断／输入哈希及完整重叠覆盖。

此路径只允许分类保持一致的实际重新审读与状态／书目更新，以及有据新增文献；科学分类变化继续走明确复议，不能伪造用户裁决。旧纳入者被新依据明确接替时，旧作者与原始判断仍校验和保留，新作者、类型、日期、摘要依据及阅读说明须全部通过。网站同 DOI 只展示一条当前记录，旧接收依据可从绑定的原始轮恢复。

覆盖窗口按审计允许的明确重叠合并，按唯一 DOI 计数，原窗口及原完整性标志分别保留；未声明重叠、覆盖空档、重复 DOI 冲突、出窗历史判断缺口或审计哈希变化均失败。公开快照给出审计引用和统计，完整逐 DOI 追溯留在正式证据文件。连续更新的清单必须绑定该审计；封存前生成并核验，封存后只能建立新轮。

### 已收录接收稿转正式发表

仅对网站此前有效收录的接收稿，根据绑定且核验通过的跨轮审计生成 `publication_transition`；历史类别必须为纳入，状态确为 accepted → published。此前排除的接收稿、首次发现即已发表的文章，不使用此标记。字段保存原接收日、正式在线发表日、前后判断哈希、原轮及状态更新轮、审计哈希；历史事件和封存输入不改写。

网站在 Spotlight 和全部文献卡片显示“接收稿已正式发表”，详情保留两种日期并注明“此前以接收稿收录，现已正式发表”。标记作为收录历史保留，后续回扫不清掉；排序及日期筛选使用真实发表日。同一 DOI 始终一条，不重复增加馆藏数量。

发布快照的 `latest_update` 分列最近一轮“新增收录”和“接收转正式发表”数量；前者按此前选定轮中从未纳入的 DOI 计算，后者仅统计该轮实际核验的已收录接收稿转发表，不能把历史标记总数或排除者的状态变化当作本轮转发表数。日常更新最终交付也须分别报告这两项，即使转发表数为 0。

### 直接发布清单

`config/release.json` 选择 `reports/runs/` 下的原始轮并钉住 `publication.json` 的字节哈希。每个清单含原始输入引用、有序的复议来源、作者及补证来源，不引用另一个发布视图。

`resolve_pending` 必须恰好解决父轮全部未决集合；`explicit_revision` 必须逐篇绑定旧判断、旧输入和明确的用户最终裁决。每步核对候选身份、窗口、冻结规则、判断输入及来源日志；不能以最新记录静默覆盖。修订按明确顺序应用，最终不得留未审或未决项。

当前迁移保留原候选与所有判断的哈希不变。作者记录直接存于采集轮，历史作者完成事件从归档中的原日志核验；不为复议复制全部作者。补证原引用不改写，`evidence_paths` 只映射当前存放位置，仍按原内容哈希核验。公开输出另列 `storage_files`，避免读者误用旧路径。

历史 `.jsonl.gz` 按解压后的原字节校验，不能继续追加。旧视图格式只为历史测试／恢复保留，当前发布不依赖嵌套目录。归档与恢复见 `docs/repository-layout.md`。

## 作者与阅读说明

### AI’s Suggestion／今日荐读

每次用户主动请求的日常文献更新完成审查后，同时发布一篇荐读；不创建固定时间自动任务。先比较本轮新收录文章的科学问题、方法启发和对网络科学读者的阅读价值，不以期刊声誉或程序评分代替选择。没有合适新文章时，从已收录且未推荐过的文章回选，显示真实发表／接收日期及“馆藏回选”。同 DOI 只推荐一次，每个推荐日期最多一篇；同日再次更新保留本期，不能伪造新荐读日期。无可用未推荐材料时保留上期日期并说明，无需强造推荐。

推荐前主代理实际核对明确摘要和审核记录，并阅读全文。写原创中英文研究问题、简短荐读说明、三条具体推荐理由、适合读者、实际审读依据与局限，突出“为什么选它”和读者能复用的经验；全文阅读用于把握论文，不逐项堆砌内容或为填满版面凑字。区分论文结果和 AI 编辑意见，不复制完整摘要、不夸大模型适用范围。已有收录／科学筛选规则不变；旧 `abstract`／`abstract_excerpt` 荐读保留真实历史依据。

全文无法取得时，向用户说明具体文章、已尝试来源和缺失材料，请用户下载并提供；保留选题等待材料，不因全文获取失败自动换篇。实际读完后再写推荐；未读完不得声称全文审读。全文审读不等于独立复现或专家评审。

用户提供的全文保存在 `.private/fulltext-library/`，归档流程见目录规范。正式全文荐读的 `review_evidence_kind` 为 `fulltext`；`screening_evidence_kind` 和原 `evidence_sha256` 继续绑定科学筛选摘要。独立 `fulltext_review` 保存 DOI、标题、版本、PDF SHA-256、公开出版方 URL、材料来源类别、页数、实际阅读时间和阅读范围，不包含私有路径或正文。公开构建验证声明及身份绑定，不访问私有 PDF；编写记录时须实际核对文件哈希和阅读范围。`reading_comment` 保存简短双语分段说明。

`daily-suggestions-2` 保留原始 `entries`，同一期修订串行追加到 `revisions`，以 `supersedes_sha256` 钉住前一条完整推荐记录，保持原推荐日期与选题；阅读时间不能早于前一条。构建检查全部历史来源、修订链及当前纳入证据，首页显示链末端版本，公开 `daily_suggestions_history` 保留旧摘要荐读与全文修订。未绑定前版、身份不符、私有字段混入或用全文哈希替换筛选摘要哈希均拒绝发布。

`config/daily-suggestions.json` 是推荐历史单一来源，按日期追加，保存 DOI、实际回读时间、原始发布轮及 `publication.json` 字节哈希、有效判断／输入／材料哈希。旧推荐保留原绑定；当前推荐的判断或证据变化时必须重新回读并明确修订，不能只换哈希。`scripts/daily_suggestions.py` 在公开快照写入前核验来源、日期、重复 DOI、当前纳入和原始判断，公开输出包含推荐历史及配置哈希，首页显示最新有效一期。未来日更提交必须同时完成此栏目；`publish_snapshot.py --check` 核验公开荐读与正式配置一致。推荐是阅读指引，不改变纳入类别或 Spotlight 名单，也不发送社交平台消息。

## 导出与验证

```powershell
python scripts/manage_runs.py check-layout
python scripts/manage_runs.py verify-archive --manifest reports/archive/legacy-2026-10-05/manifest.json
python scripts/publish_snapshot.py --out .private/work/<run-id>/release-preview
python scripts/publish_snapshot.py --check
python -m unittest discover -s tests -v
node --check site/app.js
node --test tests/test_app.cjs
```

默认输出为 `site/data`；首次合并先导出私有预览，检查后再更新正式文件。所有输入验证先于写入，无网络请求、无私有摘要读取，也不推进审读队列。`--check` 只读比对，忽略生成时间。界面变化须浏览器验收。

公开输出为 `papers.json`、`screening-report.json`、`status.json`，只含允许的书目、作者、短说明、来源、日期／类型依据与证据哈希。接收稿明确显示接收日和待发表状态，不计入已发表数。

Spotlight 由 `featured_journals` 单独控制，扩刊不会自动改变名单。首页展示最新六篇；读者详情优先统一出版方页面，取证和作者来源保留于数据与审核记录。

## 部署与边界

`main` 是当前开发与发布分支。`.github/workflows/publish-reviewed.yml` 在相关文件推送到 `main` 时校验并发布快照；网页的审核记录与规程链接也指向 `main`。

`site/` 是唯一部署目录，GitHub Pages 工作流只校验并上传已有网站文件，不采集、不补证、不启用日更。CI 对全部报告轮次的变更触发校验；只有明确选入 release 的已完成轮次影响发布。

用户确认的常规更新收尾：交付已分类文献、待人工科学裁决清单、待人工补资料清单。资料缺口须说明已试渠道、缺失字段和最小补充动作；整刊覆盖缺口即使没有具体 DOI 也须报告。两类人工队列均为空、无未审读／活跃项、无未解决覆盖阻塞且全部发布校验通过时，用户主动请求的常规文献更新可继续提交、推送和验证部署，无需再次询问选文。用户明确仅采集／预览或禁止推送时优先遵守；有任一阻塞则保留上次有效网站并等待解决。

此条件授权不适用于解释、状态检查或技能演练，不授权定时任务、科学规则变更、部署配置修改或无关代码变更；其他推送与生产部署仍须当前任务授权。正常工具审批不因条件授权而绕过。技能的执行与收尾指引见 `.agents/skills/netsci-literature-update/`。

部署记录（提交、运行 ID、产物哈希、浏览器验收）保存在本地忽略目录。完整摘要、私有中转材料与开发历史不进入 Git 或部署。技术覆盖状态保留在审核数据；首页和 About 不重复内部历史问题。

## 访问统计

首页与 About 页各在 `</body>` 前引用一段官方 Cloudflare Web Analytics module 脚本；`data-cf-beacon` 中是公开站点标识，不是账号管理密钥。统计独立于文献加载，不添加搜索、筛选或论文点击事件；About 中英文说明须与实际配置一致。

DNS 与 GitHub Pages 托管不变。上线后检查两页只有一段 beacon、脚本正常加载及网站功能，再由账号持有者核对 Cloudflare Web Analytics 后台是否收到数据。Visits 不作为去重 DAU；脚本拦截与网络故障可能漏计。无需为验证伪造访问或直接 POST 统计接口。
