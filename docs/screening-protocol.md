# 文献筛选规程

## 科学范围与类别

| 类别 | 判据 |
|---|---|
| `core` | 网络结构、网络上的动力学或网络理论／方法是主要问题与贡献 |
| `transferable_application` | 具体系统研究有明确、可迁移的网络科学方法或理论贡献 |
| `excluded` | 有身份匹配的充分材料证明范围不符，或官方明确确认非目标类型 |
| `review` | 已实际审读，仍有科学边界或必要硬检查未决 |
| `deferred_unassessed` | 尚未得到可用材料、身份匹配失败或限流未启动；未实际审读 |

审读须指出网络对象、具体网络科学问题和主要结果。网络组织的实证研究不要求提出新算法；连接图谱、成熟网络指标的常规应用、领域专门机制、预测表现或 network/graph 用语本身不足。一般非线性动力学单独不收录。不能按领域名称、题名、节点数或显式邻接矩阵自动分类。

单篇用户裁决保留于正式日志，可供相似案例参考，不推广为领域黑名单或“某应用一律纳入”。用户选文裁决、AI 辅助审读与元数据核验分别标明，不称为全文专家审定。

### 贡献边界的校准

- 使用成熟中心性、社区或相关网络方法，不单独构成排除理由。如果主要问题和结果直接解释枢纽、模块、连接重组或跨系统网络组织，实证研究可以纳入；若这些量仅服务于疾病、材料或其他领域结论，仍须检查是否有独立网络科学贡献。
- 两体／三体作用的识别不自动等同于高阶网络推断。主要解释局部细胞作用机制、活性物质或随机动力学而未建立网络组织问题或明确可迁移网络方法的研究，不因此纳入；节点数量不是排除依据。
- 图优化任务或张量网络表示不自动等同于网络科学方法。通用求解器的速度、内存或精确求解改进，须另有明确网络科学问题／贡献才纳入；不将组合优化整体排除。
- 神经网络自身是研究对象，也不自动满足范围。泛化、学习景观、固液层、老化等深度学习统计物理，须直接贡献于目标网络组织或网络动力学问题，而非仅依赖“网络”名称。
- 多层传播模型须区分渠道／群体耦合与实际接触拓扑，摘要未说明的连接机制不得补造。用户明确选择的单篇相关阅读可保留其证据限制及编辑属性，不自动推广为所有传播模型符合核心范围。

以上是对既有主要贡献原则的执行校准，不增加领域白名单或黑名单；具体裁决与理由留在正式审核轮，旧轮继续采用自己的冻结规程。

## 身份、类型与日期

- 核对 DOI、题名、期刊与白名单 ISSN。数学排版差异与实质题名变化分别处理；材料错配或不足不能靠哈希或 DOI 字符串消除。
- 不收预印本、新闻、职业新闻、选文亮点、Editorial、勘误、撤稿、书评、讣告等明确非目标类型。Review、Perspective、Analysis、Resource 等不能自动类型排除；同名栏目须逐刊解释。Reply 排除，PRL 的研究 Letter 不因此排除。Accepted Paper 是状态，不是类型。
- 日期优先为明确首次在线发表日，其次纸刊日，再 published/issued。优先字段不完整时不补造日、不静默回退。未来日期或未解决冲突进入未决；卷期日、接收日与开放归档日不冒充发表日。
- 已在线发表的 Online First／Article in Press 不需等待期号；缺少版本标签不是排除理由。
- 已授权接收稿例外：出版社确认 Accepted Paper，首次发表日尚未确认时可用完整、非未来、窗口内接收日定窗，显示已接收，`published_date=null`。不计入已发表数。
- APS 特例：同 DOI 的 Crossref online 等于官方 Accepted 且官方另有完整 Published 时采用该 Published，保留原值及理由；其他冲突不能自动套用。

### 常规研究文章的类型证据

用户已确认：所有白名单期刊，已发表及已接收的常规研究文章均可采用身份匹配的明确摘要，实际确认其提出研究问题、方法、分析或结果；同时检查目标标题和已有官方类型证据，无特殊类型线索或冲突。缺少精确 Article／Regular Article／Letter 子类型不单独阻断纳入。不能仅凭刊名、无特殊标题字样、摘要长度或通用 journal-article 标志自动认定。已知官方具体类型仍优先；特殊类型按具体证据及科学内容处理，明确非目标类型排除，类型冲突或研究性质不清保留 review。

`hard_checks.type` 使用 `basis_kind=explicit_abstract_research_inference`、`research_nature=original_research`，保存摘要材料哈希、来源、逐篇支持理由、`special_type_check=clear`、`specific_subtype=null`、`subtype_status=not_required_for_inclusion`；`status=verified` 仅表示当前政策下目标研究性质已确认，不表示官方确认了具体子类型，`value=null` 不强填 Article。网站只为有据的特殊类型显示卡片徽标。此规则只用于新冻结审核轮，不重写旧轮依据。

### PRL 接收稿的历史类型证据例外

旧轮采用的 PRL 单刊例外保留用于解释历史记录：官方接收页、DOI、标题、期刊身份须匹配，并核查可获得作者信息；须有完整明确、身份匹配的官方摘要。缺标签时可依据摘要明确的新问题、方法、分析或结果有据判断原创研究，不能自动写为 Letter。新轮使用上面的常规研究文章规则；旧轮的单刊限制不追溯修改。

`hard_checks.type` 保存 `basis_kind=official_accepted_abstract_inference`、官方来源、支持理由、材料哈希、`specific_subtype=null`、`subtype_status=unresolved`，明确这是摘要推断。日期保存 `basis=publisher.accepted`、`publication_status=accepted`、接收日与空发表日。正式发表后按同一 DOI 核对类型、首次在线日期和摘要变化，追加新证据与判断，再定窗口；旧记录保留，不重复收录。

参考：[APS 接收稿说明](https://journals.aps.org/accepted)、[PRL 类型说明](https://journals.aps.org/prl/authors)。以上是用户确认的本项目政策。

## 取证顺序

1. 固定本轮候选、配置、规程及哈希，仅审 `window_membership=in_window`。先核验本项目缓存；旧项目缓存仅按 DOI 核对身份、来源、版本和哈希后单篇复用，不作为新写入目标。
2. Crossref 精确 DOI，只接受明确 `abstract` 字段；JATS 转纯文本并记录依据。
3. 已知出版社页或已核验接口，只提取明确 Abstract 与必要元数据，网页在内存解析。
4. OpenAlex 精确 DOI，核对身份并从 `abstract_inverted_index` 重建；重复或缺失位置拒收。
5. 普通浏览器补证官方动态／拦截页，只摘明确 Abstract 与必要元数据，不绕过访问限制。
6. 仍不足则延期并记录尝试、缺口和下一步。已读但不足以裁定为 `review`；未取到可用材料为 `deferred_unassessed`。取得足够身份匹配材料即停止继续渠道；数据库可能同源，不能算独立科学证据。

description、导读句、选文说明、搜索片段和生成式摘要不能冒充明确摘要。官方 Abstract 摘段须注明不完整及访问限制；仅在足以判断时使用。官方明确非目标类型可不索取摘要，经审读者确认后排除。

### 有限证据例外

- 官方无明确摘要的短科学评论（如 Commentary、Perspective、Comment、Introduction、短科学通讯）允许在线实际审读可访问正文；保存简短判断、身份、具体类型、官方来源、时间、实际可见范围与观察哈希，不保存全文、HTML 或 PDF。普通研究文章不适用；材料不足保留未决。
- 单篇作者摘要例外仅限 PRL `10.1103/lvpn-gblk`：使用 `https://arxiv.org/abs/2609.09615v1` 的明确摘要，题名及全部 13 位作者须与官方接收页一致，记录版本、匹配观察与哈希。仅支持该篇范围排除或未决，不确认发表日期／类型，不声称版本等同，不新增预印本候选或推广一般 arXiv 取证权限。

## 审读、硬检查与留痕

采用 4 个文献任务并发取证，主代理集中实际逐篇审读；每批最多 100 篇。本批全部保存判断或明确延期才进下批，中断优先恢复已缓存未审读材料。程序只取证和记录，不自动语义分类；渠道成功、摘要非空、长度与哈希不是审读完成证据。

每渠道默认单次请求、30 秒超时、最多 4 MB；重试须针对既有失败、限定预算并记录授权与原因。Crossref 公共接口同时最多 1 请求、启动间隔至少 0.25 秒；各来源遵守更低上限，429 触发停止新任务和后续渠道。只记安全限额头，不存认证信息；限流未启动不得记作无摘要。

每篇保存规则、记录、材料与输入哈希，来源、获取时间、审读者、类别、具体理由及短证据，身份／类型／日期硬检查分别记录。官方身份与正确材料足够独立证明范围排除时，未决日期或具体类型不再阻断；保留原冲突，注明停止补核，不把未核字段标为通过。可能纳入者仍须通过全部必要硬检查。

常规研究只依标题、明确摘要及必要元数据判断，不以作者声誉、刊物名气或开放搜索填补科学事实。短证据最多 40 个英文词；纳入者另写有证据的一句话阅读说明，不夸大创新、效果或因果。输入或规则实质改变须重新核查，保留旧判断；用户裁决明确署名。取证日志由协调线程串行追加。

用户逐篇或明确组内选文裁决可作为编辑依据，须先记录 `user_editorial_verdict` 事件，包含 DOI、include/exclude、实际用户意见、意见性质和身份/材料依据；判断通过 `editorial_basis.verdict_sha256` 绑定事件。缺摘要时，仅用户明确逐篇排除且声明已亲自复核可使用 `user_editorial_decision` 排除；不得称为 AI 摘要审查或伪造摘要/类型通过。用户纳入意见不豁免身份、日期、目标研究性质检查。“倾向”单独保留为编辑方向，须由实际摘要复核或本次明确授权定案支持，不推广为领域黑名单。

## 数据边界与规则版本

完整摘要仅存本项目 Git 忽略的 `.private/abstract-cache/v9/`，保留来源、时间、明确摘要依据、内容哈希和旧版本。不得存入普通报告、Git 或 `site/`；不保存正文、HTML、PDF、cookie 或凭据。

每轮冻结规程与配置在 `reports/runs/<run-id>/inputs/`；历史判断保持原规则哈希。此工作文档用于新轮，不静默修订旧轮依据。科学、日期、类型和证据边界的实质变化须经用户确认；整理文字和迁移历史不是新科学裁决。失败或未完成不得替换上次有效网站快照。

## 执行入口

以下目录是下一轮占位路径，须先完成对应采集；现有旧轮不重复初始化。

```powershell
python scripts/screen_candidates.py --out reports/runs/example-run init
python scripts/screen_candidates.py --out reports/runs/example-run collect-batch --workers 4
python scripts/screen_candidates.py --out reports/runs/example-run review-pack --limit 100
python scripts/screen_candidates.py --out reports/runs/example-run decide-pack .private/work/example-run/decisions.json
python scripts/screen_candidates.py --out reports/runs/example-run batch --size 100
```

`review-pack` 仅在当前审读会话显示私有材料，不能把输出写进普通文件。`decisions.json` 由实际审读者按篇填写，程序不能代写科学结论；`--help` 查看单篇与批次命令。原批次完成后才调用 `batch` 选下一批，循环取证、阅读和保存。

难取材料后续使用 `scripts/supplement_evidence.py`，每次显式 `--run`。`init --authorization` 记录用户实际已授权的任务描述，不生成授权；后续依次 `begin --phase ... --size ...`、`collect`、`pack`、`save --path ...`、`close`。私有 manifest 固定本轮未决集合及候选哈希，恢复须匹配；短评论及单篇作者摘要权限不因换轮次而扩大。冻结规则不可原地替换，实质改动需保留原轮并建立经确认的新审核轮。
