# 九月文献资料收集：方法总结与网站来源说明建议

核对日期：2026-10-02。范围是本项目已有采集脚本和本次九月试验报告；本总结不进行新的联网采集，不修改网站。当前汇总依据为 `material-master-v4.json`。历史报告是当时快照，不能把其中的旧待办数当成当前状态。

## 1. 当前完成了什么

完整初始池为 3,987 个唯一 DOI，不等于九月实际应收录文章数，也不代表出版社九月全部文章已完整覆盖。

| 当前资料状态 | 数量 | 含义 |
|---|---:|---|
| 有摘要级材料和确定记录日期 | 3,518 | 沿用历史材料口径，部分含网页描述，不能全部称为已核实独立摘要 |
| 有非目标文章类型证据 | 355 | 类型证据已经收集；不计作成功补到摘要 |
| 已核查但摘要为空 | 2 | APS Accepted Paper，保留 review |
| 历史排除、本轮未重新采集 | 112 | 下一轮须核对旧理由与证据，不直接作为新 v9 结论 |

3,518 篇中，按当前记录日期：3,225 篇在九月、282 篇早于九月、11 篇在十月。材料状态、时间窗口资格、类型资格和主题筛选结果是不同维度。全体 v9 主题审读尚未完成。

## 2. “资料来源”与“获取方式”必须分开

- 资料来源：Crossref、出版社、OpenAlex、Europe PMC、PubMed、PMC、OpenAIRE 等。
- 获取方式：API、普通 HTTP 读取出版社结构化字段、授权浏览器中的页面读取、官方目录或引用导出核对。
- DOI 是文章标识和访问入口；浏览器和采集脚本是工具，都不是独立学术资料来源。
- 同一文章的标题、日期、类型和用于审读的摘要可能来自不同渠道。网站不能仅写一个“来源：Crossref”就覆盖全部字段，也不能把尝试过但未提供有效材料的 API 列为该文章的证据来源。

## 3. 实际尝试的方法及复用判断

|---|---|---|

| Crossref 单 DOI 刷新 | 11 篇 APS 原 published-online 等于九月接收日；刷新后全部变成 10 月 1 日，与出版社 Published 一致 | 对冲突、状态变化有价值；保存新旧值及访问时间，不能静默覆盖历史 |

## 4. 本次需要纠正或不宜继续沿用的方法

### 4.1 把长 description 当摘要，或仅凭字数认定摘要

旧 `publisher_structured_batch_v9.py`、`openaire_batch_v9.py`、`api_batch_v9.py` 中存在以 description 和长度推断摘要的路径。Springer 补采也有 description 回退。网页描述可能是摘要，也可能是导语、摘要截断或栏目介绍；超过 40 词并不能证明它是摘要。反过来，完整摘要也可能很短。

后期明确摘要节点读取改善了这一点，但仍有 10 词等阈值，浏览器模块还通过 Abstract 标题的父节点提取内容；这些只是启发式解析，不等于已经证明每篇完整且无混入内容。复用前应检查对应出版社模板，并将“明确摘要”“描述待核实”“摘要为空”“读取失败”分别记录。不能为方便直接重跑旧脚本作为最终审读器。

### 4.2 把卷期、接收、归档开放或聚合日期直接当首次在线发表日期

Elsevier 297 篇专项中有 280 篇在九月前在线发表，说明按卷期日期进入九月候选池会产生大量超窗候选。应先核实带明确语义的 online 日期，再决定是否值得补摘要。这个现象来自已核对的子集，不能推成全部 Elsevier 文章都存在同样时差。

APS 11 篇说明元数据会随出版状态更新，必须保留快照。接收稿无确认发表日时按已授权的 Accepted Paper 例外；有确认发表日后按规则更新同一 DOI。不能泛化为“出版社任何日期永远优先”，尤其不能再次误用卷期日期。

### 4.3 把打开失败、未索引、无独立摘要混为一谈

HTTP 200 也可能是验证页或通用页面；应核对 DOI 和所需字段。401/403、429、404、返回空字段与解析失败含义不同。后期 62 篇全部在浏览器中确认身份，新增摘要 0，说明多数缺口来自内容格式，继续申请权限或刷新不能解决。明确非目标栏目后应结束摘要搜索。

### 4.4 假定浏览器手动访问一次，外部 HTTP 脚本就得到同等权限

已验证可用的是：在原授权浏览器会话内调用脚本读取页面。没有建立“手动授权后，独立 Python HTTP 自动继承会话”的稳定方案。本次也未建立独立无人值守浏览器采集服务。两种方式不能在网站或方法说明中混写。

保留浏览器会话、有界等待、必要时正常刷新、限制请求频率是可用措施；没有证据支持一个永久有效的固定等待秒数。验证码/访问控制绕过、导出 cookie 等不属于本项目可复用方法。

### 4.5 用访问成功数、摘要标志或关键词命中代替科学审读

`abstract_available`、字数、哈希、`scope_terms` 和旧启发式分类只说明采集或线索状态。全体筛选必须按照 v9 使用实际标题、摘要及允许的元数据；不使用正文、搜索片段或自行生成摘要补缺失科学事实。

### 4.6 无变化地反复尝试相同渠道

失败样本可作一次诊断、有限重试或在服务/权限/文章状态改变后重查。不应不断遍历已确认无摘要的记录，也不应将再次统计或重写报告称为新增资料。早期 40 篇页面探测试验没有成功提取；后期 APS HTTP 与浏览器成功，说明必须限定结论到当时环境和具体端点。

## 5. 建议固定的可复用流程

1. Crossref 按白名单 ISSN 建池，记录查询窗口、总量、分页与截断状态；规范化 DOI 后去重。
2. 先做身份、文章类型、日期硬检查。优先剔除明确非目标类型和窗口外记录；冲突保留原值与裁定理由。
3. 复用已保存且来源明确的证据；需要摘要时先精确 DOI 查询已证明有用的结构化来源。聚合来源只提供候选信息，不直接覆盖明确的出版社事实。
4. 按出版社使用经过验证的页面解析路径；普通 HTTP 失败时才排入授权浏览器队列。不要让每个 DOI 无差别走所有 API。
5. 核对 DOI、字段语义与实际摘要段落；只保存允许的元数据、来源、短证据及哈希，摘要瞬时处理。
6. 按 DOI 保存检查点，重试保留旧尝试；原始数据、采集结果、裁定和正式审读分开。采用最新有效裁定，不读陈旧历史字段冒充当前状态。
7. 对仍无摘要或无法裁定者保留 review；统计唯一 DOI 覆盖与具体缺口，不承诺全部补齐。正式筛选另存 v9 版本、输入/配置哈希、审读时间、结果与证据。

保留哈希有助于判断输入是否改变，但因为项目不保存完整摘要，它不能单独重建原始审读文本。后续复核可能需要按来源重新读取；应如实说明这个可复现性边界。

## 6. 网站应当怎样展示来源

以下是建议，尚未写入生产网页，也不是所有文章已具备的统一字段。

### 全站“资料来源与筛选方法”说明草案

> 本站按期刊白名单收集文献，以 Crossref 发现候选文章并获取基础书目信息；缺失或冲突的资料通过出版社页面及可用的学术元数据服务补充核对。文章日期区分首次在线发表、接收和卷期信息，类型以可核实的出版社证据为依据。筛选使用标题、摘要和必要元数据，不进行全文专家评审；证据不足的文章保留待复核。本网站展示书目信息、来源链接及筛选说明，不转载完整摘要或论文全文。

仅在九月试验正式上线时采用与最终实现一致的文案；当前生产仍为 v8 固定基线，不能提前描述成已上线的全量 v9 服务。

### 每篇文章“来源与核验”折叠项

| 信息 | 建议显示 |
|---|---|
| 原文 | DOI 和出版社文章链接 |
| 基础书目来源 | 实际采用的 Crossref 或其他来源 |
| 日期依据 | 采用日期、原始标签，例如 Published / online / Accepted，及来源链接 |
| 类型/状态 | 文章类型、Accepted Paper 等状态及证据来源；两者分开 |
| 审读材料来源 | 真正提供本次审读摘要的来源；仅成功访问或提供描述的来源不冒充摘要源 |
| 核验时间 | 对应证据的实际访问日期；本地合并时间不等于网页复查时间 |
| 裁定说明 | 存在冲突时简短说明，例如旧 online 值等于接收日、刷新后与出版社一致 |
| 筛选信息 | 规则版本、类别和有具体依据的一句收录说明；与资料来源分开 |

正文列表可只显示 DOI/原文入口、日期和必要状态，详细来源放在折叠项。API 错误码、脚本文件名、内部路径和完整请求日志适合内部报告，不必出现在文章卡片。未实际提供证据的失败渠道不列为该篇来源。

网站可公开汇总真实使用的服务，但不宜给出各渠道互斥“贡献篇数”：目前不同轮次覆盖重叠、证据粒度也不同，尚未建立逐字段最终采纳来源的全池归因统计。现有证据链是基础，公开展示前仍需统一映射。

## 7. 本次总结的边界

本报告依据本地已有记录与脚本作方法审计，未新增验证各服务目前的套餐、许可或可用性；不把没有跑通 API 写成不存在 API，也不把校园访问成功当作批量 API 权限证明。没有重新采集论文、修改生产数据、部署网站或改动筛选定义。
